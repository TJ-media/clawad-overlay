# 카피레프트 경계 규칙 (AGPL 격리)

clawad-overlay는 AGPL-3.0이고, ClawAd 서버(광고·4원장·리워드·정산)는 비공개다. AGPL의 카피레프트가 서버로 번지지 않도록 아래 규칙을 **반드시** 지킨다.

## 1. 통신은 네트워크 API로만

- 이 클라이언트와 ClawAd 서버는 **HTTP API로만** 통신한다.
- 어느 쪽도 상대의 소스를 `import`/`require`/링크하지 않는다. 코드 수준 결합이 생기는 순간 "하나의 프로그램"으로 간주돼 서버까지 AGPL이 번질 수 있다.

## 2. 공유 코드 취급

- 클라이언트와 서버가 공유해야 하는 것(예: API 요청/응답 스키마)은 **문서화된 프로토콜**로 두는 것을 기본으로 한다.
- 코드 공유가 불가피하면, 그 조각만 **permissive 라이선스(MIT 등)로 별도 관리**하고 AGPL 코드와 섞지 않는다.
- ClawAd 서버의 `packages/shared-contracts` 같은 모듈을 이 저장소에서 직접 링크하지 않는다.

## 3. upstream(clawd-on-desk) 준수

- 포크한 clawd-on-desk 코드의 **원저작권 표시·라이선스 문구를 보존**한다.
- 우리가 변경한 부분을 **명시**한다(AGPL 요구).
- upstream의 **아트워크·번들 테마 에셋은 가져오지 않는다** (All rights reserved). 캐릭터는 ClawAd 자체 제작 마스코트만 사용한다.

## 4. 우리 아트워크

- ClawAd 마스코트 아트워크(SVG·PNG)는 코드와 분리해 **© ClawAd, All rights reserved**로 둔다. 코드는 AGPL로 공개하되 캐릭터 IP는 보유한다.

## 5. 배포/공개 시점

- AGPL §13(네트워크 사용 시 소스 제공) 의무는 **실제 배포·서비스 시점**에 발생한다.
- 공개 배포 전 코드서명·상표 점검은 ClawAd 측 이슈(CLAW-94/95)에서 별도로 다룬다.
