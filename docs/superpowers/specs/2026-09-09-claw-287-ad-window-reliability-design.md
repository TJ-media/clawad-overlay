# CLAW-287 광고창 가시성·상태 동기화 설계

## 목표

- 작업 시작 시 이미 캐시된 광고를 마스코트와 체감상 동시에 표시한다.
- 작업이 끝나면 광고 표시와 노출 구간을 즉시 끝낸다.
- Windows에서 광고창을 일반 애플리케이션의 최상단 창보다 위에 유지하되, 마스코트와 그 입력창보다는 아래에 둔다.
- 절전 복귀, 잠금 해제, DWM cloak, 렌더러 중단 뒤 빈 광고창이 남지 않도록 자동 복구한다.
- 실제 렌더 완료 전 시간은 노출 사실로 기록하지 않는다.

## 관찰된 원인

평상시 작업 상태 파일을 읽는 주기는 약 1초라서 캐시가 있으면 표시 지연은 대체로 1초 이내였다. 그러나 광고 번들이 비어 있던 실제 사례에서는 다음 주기 동기화를 기다리며 약 16초가 걸렸다. 또한 기존 구현은 메인 프로세스가 렌더 명령을 보낸 시각부터 노출 구간을 열기 때문에, 창이 DWM에 의해 가려졌거나 렌더러가 멈춘 경우에도 화면에 픽셀이 없는 시간이 표시 사실에 포함될 수 있었다. 일시중지 후 재개가 고친 것은 광고 BrowserWindow 재생성이 cloak/렌더러 상태를 초기화했기 때문으로 판단한다.

## 설계

### 1. 준비와 표시 확인을 분리한다

광고 런타임은 `tick()`에서 표시 후보와 로컬 `renderId`를 반환하되 노출 구간은 열지 않는다. 렌더러가 DOM을 갱신한 다음 두 번의 animation frame을 지난 뒤 `renderId`를 메인 프로세스로 되돌려 보낸다. 메인 프로세스는 현재 창·현재 후보의 ACK인지 검증하고 `confirmRendered(renderId, paintedAt)`를 호출한다. 이때부터만 `renderStarted`와 `displayStartedAt`을 기록한다.

ACK를 받기 전 후보가 바뀌거나 숨김 상태가 되면 후보를 취소한다. 정해진 시간 안에 ACK가 오지 않으면 현재 창을 폐기하고 새 BrowserWindow를 만들어 다시 시도한다. `renderId`는 프로세스 내부 상관관계 값이며 스풀이나 네트워크로 전송하지 않는다.

### 2. Windows 최상단 순서를 한 곳에서 관리한다

광고창도 중앙 topmost watchdog에 등록한다. watchdog의 재적용 순서는 다음과 같다.

1. 광고창
2. 마스코트 창
3. 마스코트 입력 창

동일한 Windows topmost 레벨에서 뒤에 재적용한 창이 위로 오므로 광고는 외부 최상단 창보다 위, 마스코트보다 아래에 놓인다. 전체화면 앱 앞에서는 기존 정책과 동일하게 광고·마스코트 모두 topmost 재적용을 쉬며, 사용자가 전체화면 오버레이를 켠 경우에만 유지한다.

### 3. 창 장애를 자동 복구한다

광고창은 `render-process-gone`, `unresponsive`, `did-fail-load`를 감지한다. 실패 시 미확인 후보를 취소하고 창을 폐기한 뒤, 작업 중이면 다음 tick에서 재생성한다. Windows에서는 watchdog과 `resume`/`unlock-screen`에서 광고창 cloak 복구를 실행한다. 복구는 보이는 창만 대상으로 하고, 실패해도 앱 전체를 종료시키지 않는다.

### 4. 작업 상태와 즉시 맞춘다

광고의 화면 가시성은 최근 종료 구간을 포함하는 유예값이 아니라 `active: true`인 현재 작업 세션만 사용한다. 좀비 세션 방지를 위한 stale 제한은 유지한다. `work-state` 디렉터리를 감시해 변경 시 즉시 tick하고, 파일 감시가 끊겨도 기존 1초 poll을 안전망으로 유지한다. 따라서 정상 캐시 상태 목표는 작업 시작 후 500ms 안팎, 작업 종료 후 300ms 안팎의 표시 전환이다.

### 5. 빈 캐시를 능동적으로 보충한다

작업 중이지만 유효한 번들이 없으면 검증된 CLI sibling 명령을 한 번 실행해 즉시 동기화를 요청한다. 요청은 프로세스당 in-flight 중복과 cooldown을 적용한다. 동기화 동안에는 로컬 안내 문구를 표시해 사용자가 고장으로 오해하지 않게 하고, 번들 파일 변경을 감지하면 즉시 광고로 전환한다. CLI가 없거나 동기화가 실패해도 주기 동기화와 기존 안전한 안내 동작은 유지한다.

## 개인정보·정산 경계

- 새 네트워크 이벤트나 텔레메트리 필드를 추가하지 않는다.
- `renderId`와 복구 상태는 로컬 프로세스 안에서만 사용한다.
- 스풀 스키마와 서버 판정은 바꾸지 않는다.
- 광고 문구의 `[광고]` 표기는 유지한다.
- 프롬프트, 경로, 코드, 환경 변수는 수집하거나 기록하지 않는다.

## 검증

- 런타임 단위 테스트: ACK 전에는 스풀이 생기지 않고 ACK 시각부터 구간이 시작된다.
- 렌더러 테스트: 두 animation frame 이후 정확한 `renderId`를 ACK한다.
- 창 테스트: ACK timeout과 renderer failure에서 창을 재생성하고, IPC sender/ID가 틀리면 무시한다.
- topmost 테스트: 광고 → 마스코트 → 입력창 순서를 보장하고 전체화면 stand-down을 유지한다.
- 활동 테스트: 종료 이벤트 직후 광고가 숨겨지고 파일 변경이 poll보다 먼저 tick을 유발한다.
- 회귀 검증: 관련 테스트, 전체 `npm test`, 변경 파일 구문 검사를 실행한다.
