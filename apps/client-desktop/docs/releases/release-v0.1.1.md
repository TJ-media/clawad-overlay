## v0.1.1

클로애드 CLI가 Claude Code의 `statusLine` 슬롯에서 물러나면서(CLAW-134), 오버레이가 그 자리를
이어받아 Claude 구독 쿼터를 표시할 수 있게 됐다. 그 과정에서 드러난 노출 인정 손실도 함께 고쳤다.

### 새 기능

- **Claude 구독 쿼터 수집 기본 활성화** (CLAW-136) — `claudeQuotaCollectionEnabled` 기본값을 켜짐으로
  바꿨다. 그동안 쿼터 링·대시보드에 Codex만 뜨고 Claude는 비어 있었는데, 이는 CLI의 광고 상태줄이
  `statusLine` 슬롯을 점유해 오버레이가 `rate_limits`를 받을 수 없었기 때문이다. CLI가 슬롯을
  비웠고(clawad v0.1.12), 이제 기본으로 이어받는다.

  상류는 이 기능을 opt-in으로 뒀지만 ClawAd는 기본 활성으로 간다 — 설정을 열지 않는 사용자에게
  쿼터 링이 계속 빈 채로 남기 때문이다. 다음 조건은 그대로 지킨다.

  - 값은 **단말을 벗어나지 않는다.** 운영자 서버로 전송하지 않는다
  - **비어 있는 슬롯만** 쓴다. 사용자가 쓰던 statusLine이 있으면 건드리지 않고 수집을 포기한다
  - 설정에서 끌 수 있고, 앱을 제거하면 슬롯을 원래대로 되돌린다
  - **이 자리에 광고를 표시하지 않는다.** 광고 창구는 오버레이 본체 하나뿐이다

- **설정에 로그인 상태와 로그인 버튼** (CLAW-137) — 설정 → 일반 맨 위에 "클로애드 계정" 섹션을
  추가했다. 그동안 오버레이는 인증 상태를 전혀 읽지 않아서, 로그인이 풀리거나 약관·방침이 개정돼
  적립이 멈춰도 **화면에 아무 설명이 없었다.** 실제로 처리방침 v3 시행 때 그 상황이 발생했다.

  이제 상태를 문구로 알리고, **로그인으로 해결되는 상태에만** 버튼을 띄운다. 서버 연결 장애처럼
  로그인이 소용없는 상태에는 버튼을 감춘다 — 있으면 엉뚱한 조치를 하게 된다. 버튼을 누르면
  브라우저에 로그인 화면이 열린다.

  인증은 CLI가 전담한다. 오버레이는 로그인 정보의 **존재 여부**와 동기화 오류 코드만 읽고
  토큰 값은 읽지 않는다.

### 버그 수정

- **연속으로 본 광고가 서로 미인정되던 문제** (CLAW-135) — 서버는 동시 노출 판정 구간을
  허용 오차만큼 양쪽으로 넓히는데, 로테이션이 표시 구간을 0ms 간격으로 붙여 만들어 연속 노출이
  서로 충돌했다. 실측으로 약 3분의 1이 적립에서 빠지고 있었다.

  이제 새 인정 구간의 시작을 직전 구간 종료로부터 `adGapMs`만큼 미룬다. 신고하는 구간이 실제
  표시 구간의 부분집합이 되므로 과대 신고가 아니고, 실제 첫 렌더 시각(`renderStarted`)은 그대로
  유지해 표시 시작 진단의 의미를 지킨다.

  **화면은 달라지지 않는다.** 광고창이 사라졌다 다시 뜨면 사용자 피로가 생기므로 틈은 인정
  구간에만 두고, 광고는 지금처럼 끊김 없이 문구만 바뀐다.

### 호환성

- `adGapMs`는 정책 캐시의 **선택 항목**이다. 이 키를 쓰지 않는 구 버전 CLI와 함께 있어도 광고는
  계속 표시되며, 간격 없이(이전 판과 동일하게) 동작한다. 오버레이는 자동 업데이트되고 CLI는 수동
  업데이트라 이 조합이 실제로 생기기 때문이다. 정책 캐시 버전은 올리지 않았다 — 올리면 반대 조합
  (새 CLI + 구 오버레이)에서 구 오버레이가 광고를 꺼버린다.
- 따라서 **CLI와 오버레이의 릴리스 순서는 무관하다.**
